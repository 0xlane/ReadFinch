# 配置管理与服务商

## 品牌升级

ReadFinch（伴读雀）沿用原 TextHop 的本机存储与加密身份。已有配置、凭据和 SQLite 笔记无需导出重建；历史 WebDAV 路径继续生效。参见 [品牌与升级说明](brand/READFINCH.md)。

## 自动保存

设置不需要点击保存。普通配置停止输入约 400 ms 后写入，API Key 约 650 ms 后单独加密保存，WebDAV 连接约 500 ms 后保存；主题立即生效。自定义 AI 指令使用同一套自动保存机制。

输入过程中的无效 URL 或未完成字段留在草稿中，显示“待完善”，不覆盖上次有效配置。保存回执不会覆盖仍在输入的新内容。关闭设置窗口是隐藏到托盘，待保存任务继续运行；退出整个进程前应看到“已保存”。测试连接、导入、恢复和同步仍是显式按钮操作。

API Key 空白输入框表示不更改已有密钥；使用移除按钮才删除密钥。所有模型测试先保存当前有效设置和已输入的凭据。

## API 提供商

每个提供商维护一个模型、API 地址、推理强度、温度和连接选项。同一账号可通过「复制」创建第二个提供商，再修改模型。每个指令、语言检测、在线朗读和 OCR 都按提供商 ID 分配。模型 ID 和推理强度在「API 提供商」中编辑。「提供商默认」让模型决定推理强度，显式选择的强度通过 `reasoning_effort` 随请求发送。自定义请求头以 JSON 对象填写，经过校验后按地址加密保存在本机。导出和 WebDAV 同步包含推理强度、温度与用途，不含 API Key 或请求头。详见 [API 提供商与功能分配](MODELS.md)。

在提供商「高级选项 → 代理」中，可选择使用全局代理（跟随系统）、禁用或自定义代理。配置自动保存，复制、导出和配置同步会保留代理模式与地址。详见 [提供商代理](PROXY.md)。

## 文本转语音

按语言选择音色，或为未分配的语言指定兜底声音。首次使用和从旧版升级时都会自动匹配本机语音。各语言可分别选本机或在线声音。朗读按钮和试听按钮均可再次点击停止，从其他窗口开始播放也会终止上一段朗读。

在线朗读使用「API 提供商」中支持 `/audio/speech` 的语音模型。可以使用内置音色 ID 或添加自定义 ID。只有使用在线音色时才会把待朗读文本发给语音提供商。语速、音高和音量均可调节，0 为基准，可一键恢复默认。

## 自定义 AI 指令

在「配置」标签选提供商、编辑提示词和输出 Schema。模型生成的字段支持字符串、数字和 `null`。选「选中的文字」会原样使用本次选区。字段有独立 ID，改名时会同步更新版式中的引用，调整顺序会改变默认卡片顺序。

在「版式」点「编辑版式」可用 HTML + Liquid 编排卡片。例如 `{{ ["释义"] }}` 取字段值，`ctx.selection` 是原文，`ctx.fields` 提供有序字段。预览与结果窗共用渲染器。模型值会转义，模板可以显示文字、布局和使用当前语音设置的朗读按钮。

在「笔记库」标签设定本地笔记本、标题字段和字段名。手动收藏与「猜你想存」都会保存当时的字段和版式。之后修改或删除指令仍可查看历史笔记。旧配置中自行修改过的指令保留原输出格式，点「配置输出字段」可启用 Schema。

v13 升级到 v14 时，为没有代理设置的提供商补充「使用全局代理」，跟随操作系统。已有模型、账户、凭据和用途保持不变。

v12 升级到 v13 时，提供商保留最后选择的内置模型，便于从自定义模式切回。只补全旧版为空的预置模型；已经选择的非空 ID、私有 ID 和用途保持不变。

v10 升级到 v11 时默认使用本机语音。配置迁移包含已选择的音色 ID，更换设备后缺少的系统声音会回退到可用语音。

v7 升级至 v8 时添加推荐偏好。推荐请求使用选区开头最多 1,500 个字符，以及手动补充说明开头最多 2,500 个字符。选中的原文保存在词条的本地摘录中，可以在笔记库中搜索。修改推荐设置后自动保存，配置导出和 WebDAV 只携带偏好。

v6 升级至 v7 时清理六条从未修改的旧示例指令，保留用户调整过的指令和绑定。v4 和 v5 中同一账号的多个模型会拆成独立提供商。已分配的指令、OCR 与语言检测会指向对应的提供商。本机升级在原地址范围内复制加密凭据。一小时暂停期限单独保存在本机。

变量：`{{text}}`、`{{context}}`、`{{sourceLanguage}}`、`{{targetLanguage}}`、`{{explanationLanguage}}`。只做一次替换，原文本身含变量语法时不会二次展开。上下文仅为用户手动提供的内容。

schema 严格拒绝未知字段、重复 ID、无效服务引用、不支持的版本、URL 内凭据和冲突快捷键。普通导出不含任何凭据、模型权重、图片、选中文字、历史、日志、本机路径或窗口位置。

v1 中 `shortcuts.selection` 实际直接执行翻译。升级到 v2 时将这个原有组合键移入翻译指令的 `shortcut`，将指令菜单入口留空；不会把原来的翻译键改成菜单键。词典和润色默认增加 `Alt+Shift+D`、`Alt+Shift+W`，若与现有键冲突则不自动启用。v0 先补充阅读字号再迁移。v4 导出的文件需要 TextHop 0.4.0 或更新版本；同步设备也应升级。

v2 的文字和 OpenAI 视觉服务迁移到同一个 `providers` 列表，保留模型、端点、指令引用和默认选择；文字/视觉原 ID 重复时自动分配新 ID。仅本机启动升级时复制相应的 OS 加密凭据，且必须匹配原端点；普通导入或 WebDAV 不传输密钥。旧 Ollama 专用服务不再启用，原默认若指向它则回到内置离线 OCR；原文件在首次保存时保留为 `.bak`。离线 OCR 始终由固定的 `ocr-offline` 引用，不作为可编辑服务商。

v3 → v4 自动将服务商的原文字模型、视觉模型与各指令覆盖模型收集进模型库，保留原引用与加密凭据。内置目录仅作为搜索候选，不限制自定义 ID。

新配置使用 `Alt+T` 翻译、`Alt+Shift+D` 词典、`Alt+Shift+W` 润色、`CommandOrControl+Shift+Space` 选区指令菜单。截图与剪贴板入口保持 `CommandOrControl+Shift+2` / `CommandOrControl+Shift+V`。快捷键随配置导出和同步；停用指令释放系统注册，复制指令不复制其快捷键。

在设置输入框按组合键录入，Esc 取消本次录入，Backspace/Delete 清空。录入期间暂停应用快捷键，结束或窗口失焦后恢复。冲突按当前系统解释修饰键与别名，保留上次有效设置；其他应用占用组合键时在快捷键区域显示注册失败，不声称该组合键已可用。

导入先校验，再展示数量、映射后的快捷键及目的设备需要补充的凭据。合并按稳定 ID 覆盖同 ID 项，同时保留其他本机项；重复导入不会新增重复指令。替换完整采用导入配置。两种操作都先建立备份，并用配置内容摘要检查预览期间有无其他窗口修改。

## 本机恢复

主配置写入采用同目录临时文件、flush/fsync、rename。保存前维护 `config.json.bak`；导入、同步拉取和冲突还会保留命名备份。读取到无效配置时将损坏原件保存为 `config-invalid-*.json`，尝试恢复上一个有效备份，并在 UI 提示。失败不会静默覆盖原文件。

本机数据目录可通过“设置 → 配置管理 → 打开数据目录”查看。

- `config.json` 保存可迁移配置。
- `local-notes.sqlite` 保存本机收藏的原文和结果，独立于配置导出与 WebDAV。
- `credentials.enc.json`：OS 加密的凭据，附带服务端点绑定；不参与配置同步。
- `device-sync.json`：本机 WebDAV URL、账号和启用状态。
- `sync-baseline.json`：最后同步的内容 SHA-256、ETag、端点和成功时间。
- `backups/`：可恢复的配置快照。

凭据没有安全密钥环时仅放内存，不退化为明文持久化。导入配置后如果 ID 的端点发生变化，旧凭据不会被用于新端点，界面会显示缺少凭据。

## WebDAV 设置

WebDAV、导入/导出和备份恢复合并在“配置管理”页。普通配置会自动保存；同步、导入和恢复仍需显式点击。

填写 HTTPS 服务器 URL、用户名、应用密码和相对配置路径，例如 `TextHop/config.json`。先在服务器建立父目录。只访问这一份配置资源，不遍历或修改其他服务器文件。同步默认关闭，第一版只提供手动同步。

“测试连接”读取并校验目标配置；不存在时报告可创建。写入权限需要在实际同步时验证。认证失败、无效 JSON、未知 schema、服务不可达和传输中断会显示错误，保留本机有效配置。

每次测试或同步固定使用开始时的服务器与凭据，其他窗口修改设置不会重定向正在进行的写入。远程内容按实际读取字节限制为 2 MB，包括未提供 Content-Length 的分块响应。

## 同步状态机

1. 读取并校验远程内容。以规范化内容的 SHA-256 比较本机、远程与上次同步基线，时间戳只用于展示。
2. 首次两边都存在且内容不同：必须明确选择本机或远程。
3. 仅本机改变：上传。创建使用 `If-None-Match: *`；更新使用服务器返回的强 ETag + `If-Match`。
4. 仅远程改变：备份本机后下载；保存前重新读取远程，并核对本机 revision。
5. 两边都改变：保存双方配置快照，展示差异内容，等待明确选择。数组删除也改变摘要，因此不会被“补齐合并”悄悄恢复。
6. 解决冲突前重新获取远程并核对原冲突 token、双方内容和 ETag；任一变化都会重新进入冲突状态。
7. 远程文件被删除：进入冲突；选择保留本机才重新创建，不能悄悄重建。
8. 缺少强 ETag：禁用更新上传；可明确选择下载，或更换支持条件请求的服务。`412` 不重试无条件 PUT。
9. 上传后回读验证一致性才记录基线。失败保留旧基线，以便下一次重新判断。

服务器必须正确实现 HTTP 条件请求；客户端无法让忽略 If-Match 的服务器具备原子并发保护。当前对真实本机测试服务器的条件请求路径已经验证，用户自己的 NAS/WebDAV 仍需实际连接验收。
