# 提供商代理

在 **API 提供商 → 选择提供商 → 高级选项 → 代理** 中配置。每个提供商独立设置，修改后自动保存。

| 模式 | 行为 |
| --- | --- |
| 使用全局代理 | 默认选项，跟随操作系统的代理及其绕过规则。应用不会修改系统代理。 |
| 禁用代理 | 此提供商直接连接，不使用系统代理。 |
| 自定义代理 | 此提供商使用填写的代理。地址为空或连接失败会报错，不回退为直连。 |

自定义地址支持无需认证的 HTTP、HTTPS、SOCKS4 和 SOCKS5 代理，例如：

- `http://127.0.0.1:7890`
- `https://proxy.example:8443`
- `socks5://127.0.0.1:1080`

地址只包含协议、主机与端口，不接受账号、密码、路径、查询参数或多个代理规则。HTTPS 代理的证书按系统信任链正常校验。自定义代理也应用于本地 API 地址；本地服务需要直连时选择「禁用代理」。

模型列表、连接测试、翻译、自定义 AI 指令、猜你想存、LLM 语言检测、远程 OCR 和在线朗读均遵循其对应提供商的代理。内置离线 OCR 和系统语音无需网络。

切换模式会保留上次自定义地址。复制提供商时复制代理配置；配置导出、导入和 WebDAV 配置同步保留模式与地址。升级旧版配置时默认使用全局代理，不修改模型或 API 凭据。

新请求使用保存后的配置，已经开始的流式请求继续使用原连接。各提供商的自定义和直连通道相互隔离，模型发现缓存与结果缓存也区分代理配置。

实现使用 Electron 的 [Session 网络接口](https://www.electronjs.org/docs/latest/api/session#sesfetchinput-init) 和 [代理配置](https://www.electronjs.org/docs/latest/api/structures/proxy-config)。回归测试使用隔离应用配置和本机 HTTP、HTTPS、SOCKS 代理，覆盖实际路由、流式取消、复制、重启与失败不直连；系统代理通过隔离会话模拟，未改动操作系统设置。[验证记录](proxy-verification.json)
